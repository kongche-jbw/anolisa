2. 六个副作用阶段

逻辑对象使用 JSON 展示，真实 wire 使用 bincode。

01 CLI command 02 Request 03 Wire 04 Admission 05 Persist 06 Response
01

调用者提交 CLI 参数

用户或 Agent → cosh-cli
CLI command
workspace/home/agent/project需要保存的工作区。
idbefore-change本次快照的稳定标识。
messagesafe point说明创建目的。
CLI 先确认 workspace 路径存在，再创建 CkptClient。
02

Client 建立逻辑请求

cosh-cli → CkptClient
Request
variantRequest::Checkpoint当前 legacy 创建请求。
workspace / id/home/agent/project · before-change定位工作区和快照。
metadata / pinnull · false本例不附加元数据，也不固定快照。
请求没有 AW invocation id、manifest digest 或 operation digest。
03

Client 编码 Unix socket 帧

CkptClient → ws-ckpt daemon
Wire
socket/run/ws-ckpt/ws-ckpt.sock本地 daemon 地址。
frame[u32 little-endian length][payload]四字节长度加请求正文。
encodingbincode真实 wire 编码。
timeout5000 ms默认 socket I/O 上限。
文档中的 JSON 只是字段示意，不能当作 JSON RPC 请求发送。
04

daemon 完成准入与检查

ws-ckpt daemon → Snapshot Manager
Admission
peer identityUnix peer UID识别真实本地调用者。
workspaceownership + path checks限制调用者可操作的目录。
bootstraplegacy auto-init / adopt必要时注册工作区。
snapshot checksquiescence · unique id · non-empty创建前检查。
空工作区会得到 CheckpointSkipped，不会生成虚假的 snapshot id。
05

Snapshot Manager 持久化状态

Snapshot Manager → Btrfs + index
Persist
snapshotbefore-change创建 Btrfs 只读 CoW 快照。
parent_idprevious head建立快照 DAG 父子关系。
headbefore-change更新工作区当前快照。
indexSnapshotMeta保存可查询的元数据。
此阶段已经产生文件系统副作用，响应丢失不能证明未创建。
06

创建结果返回调用者

daemon → CkptClient → cosh-cli → 调用者
Response
daemon responseCheckpointOk { before-change }daemon 确认快照创建成功。
oktrue统一 COSH 响应成功。
skippedfalse本例实际创建了快照。
workspace/home/agent/project回显操作目标。
当前响应不会产生 AW ProviderReceipt，也不会写入 AW Ledger。

3. 三种结果语义

Created

response
CheckpointOk
meaning
快照和索引已经创建。

Skipped

response
CheckpointSkipped
meaning
已确定没有创建快照，退出码仍为 0。

Transport failure

response
missing or invalid
meaning
请求写出后可能已经产生副作用，不能盲目重试。
Future boundary
未来接入 AW 需要 Enforce authority 和可核对的副作用证据。 目标方案可复用 GuardedCheckpointV2 的 operation_digest 与 durable evidence，并增加 local-service driver、Reconcile 和 Uncertain 状态。当前 one-shot Host 明确不接纳这类 Enforce 操作。
